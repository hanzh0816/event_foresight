# v3.1 模型与服务器交接

本实现按 `/root/papers/projects/event-rgb-wm/research-v3.1.md` 的 2026-11-26 方案构建。目标是在固定 +50 ms 下比较 RGB 基线与 Event-RGB；默认 predictor 和 RVT 从头联合训练，DINOv2 保持冻结。

## 输入数据与时间边界

默认一条训练样本包含五帧连续 RGB。前四帧作为历史输入，后四帧特征作为右移一位的监督目标。四个预测并行计算，每个 query 有自己的观测截止时刻。以 `0/50/100/150/200 ms` 为例，预测 `100 ms` 的 query 只能读取截至 `50 ms` 的 RGB 和事件。

每个历史时刻 `t` 对应事件区间 `[t-50 ms, t)`。区间内均分 10 个时间 bin，分别计数正负事件，得到 20 通道。通道顺序是负极性的旧到新 10 bins，再接正极性的旧到新 10 bins。先在传感器分辨率上做 `log1p(count)`，再双线性缩放到 `512×1024`。活跃区 mask 直接统计压缩与缩放前的原始事件；默认每个 DINO patch 至少一个事件即活跃，可通过 `data.event_activity_threshold` 调整。

RGB 使用 `448×896` 输入，对应 DINO 的 `32×64` patch 网格。数据目录沿用 DSEC detection：

```text
DSEC/
  train/<sequence>/
    images/left/distorted/000000.png
    images/timestamps.txt
    images/left/exposure_timestamps.txt  # 可选，v3.1 事件窗以 RGB timestamp 为准
    object_detections/left/tracks.npy
    events/left/events.h5
  test/<sequence>/...
```

`images/left/distorted` 必须是映射到左事件相机图像平面的 `640×480` RGB，检测框与原始事件共享这个平面。代码不对事件单独应用 `rectify_map`。原生 RGB 相机图像需要先完成标定与映射，不能仅调整尺寸后代入。HDF5 reader 使用 `t_offset` 恢复绝对微秒时间，按半开区间读取事件；事件覆盖不足会报错，避免悄悄改变 RGB 与 Event-RGB 的样本集合。

历史 inventory 沿用原有 40 帧可用性条件，模型实际取最后四帧。训练增强同步水平翻转 RGB、事件、活跃区 mask 与检测框，保持事件极性不变。

## 模型结构

| 模块 | 实现 |
| --- | --- |
| RGB encoder | 冻结 `dinov2_vitb14_reg4`，取末层 LayerNorm 后的 patch tokens，去 CLS/register tokens；768 维，无 PCA 或额外 L2 normalization |
| RGB context | `Linear(768,768) + LayerNorm` |
| RVT-S | 四阶段通道 `48/96/192/384`，stride `4/2/2/2`；每阶段重叠卷积、Block-SA、Grid-SA、逐像素 LSTM |
| Event neck | S2 下采样、S3 通道投影、S4 上采样，各变为 256 通道后相加；`3×3 Conv + GroupNorm + GELU`，再 `Linear(256,768) + LayerNorm` |
| Predictor | 8 层、768 维、12 heads、FFN 3072 维，Pre-LayerNorm |
| 每层更新顺序 | RGB Cross-Attention、带门控的 Event Cross-Attention、帧内 Spatial Self-Attention、FFN |
| 输出 | `LayerNorm + Linear(768,768)`，每个目标帧 `2048×768` |

RGB 和 Event 使用独立的 Q/K/V、独立 Softmax。第 `l` 层事件更新乘以标量 `tanh(gamma_l)`；从头训练默认 `gamma_l=0.1`。RGB 预训练初始化对照将其置零，使初始预测与导入的 v3.1 RGB 基线一致。

3-Axial RoPE 每个 head 用 24 维编码行、24 维编码列、16 维编码时间。时间单位为秒，空间坐标为 RGB patch 中心坐标。紧凑 Event KV 的坐标映射回同一图像平面。旋转周期采用 `logspace(-2,2)`，角度为 `2*pi*coordinate/period`；周期选择是本实现的具体配置。Cross-Attention 以观测截止时间构造因果 mask；Spatial Self-Attention 将目标帧分别处理，目标帧之间不交换 query 信息。

RVT 的 Block-SA 使用连续窗口，Grid-SA 使用间隔采样的全局网格。默认每阶段一组 Block/Grid，head_dim 为 24，partition 为 `8×16`，LayerScale 为 `1e-5`。LSTM 在每个位置保存独立隐状态和细胞状态，仅沿当前 clip 的时间轴递推。每次常规 forward 从零初始化；显式 streaming API 可传入并返回四阶段状态，调用者负责同一流的样本顺序。细胞累加使用 FP32。

默认 Event KV 为 `32×64`。`model.event.output_stride: 32` 改用 S4 的 `16×32` 紧凑 KV；训练对齐损失将其插值回 RGB 网格。`model.predictor.event_layers: [2,4,6,8]` 可仅在偶数层加入事件注意力。默认全部八层融合。

预测器支持 query chunking 和 activation checkpointing。RVT attention 对独立窗口的 batch 轴分块，保留每个窗口内部完整注意力。下文记录了真实样本前后向的显存，包含 optimizer 状态的训练显存与吞吐尚待测量。

## 损失与梯度

主预测损失为所有样本、四个目标时间、空间 patch 和特征维度的平均 `SmoothL1(beta=1.0)`，RGB 与 Event-RGB 完全一致。前景或事件活跃区不改变主损失权重。

完整 M2 使用：

```text
L_total = L_pred + 0.1 * L_align
L_align = active_mean(SmoothL1(e_t, z_t) + 0.2 * (1 - cosine(e_t, z_t)))
```

`e_t` 为 RVT + neck 输出，`z_t` 为同一历史时刻的冻结 DINO 特征。辅助损失先对每个样本、每个时间步的活跃 patch 求均值，再对样本和时间平均；没有活跃 patch 的项贡献零。DINO target 均停止梯度。预测损失经过 Event Cross-Attention 回传至 RVT，辅助损失直接训练 RVT 和 neck。共享检测头只参与 predictor 的验证指标，不参与其训练损失。

## 配置与训练预算

| 组别 | 配置 | 训练内容 |
| --- | --- | --- |
| B1 | `configs/predictor.yaml` | 纯 RGB predictor |
| M1 | `configs/event_no_align.yaml` | RVT + Event-RGB predictor，`align_weight=0` |
| M2 | `configs/event_predictor.yaml` | RVT + Event-RGB predictor，`align_weight=0.1` |
| 共享头 | `configs/detector.yaml` | 真实 RGB 冻结 DINO 特征上的 Deformable DETR |

配置通过 `extends` 递归合并；M1 继承 M2，M2 继承 B1。比较时保持相同数据、种子、更新预算及共享检测头。各配置已指定 `stage` 和 `output_dir`，训练只需传 `--config`。

| 配置字段 | 用途 |
| --- | --- |
| `stage`、`output_dir` | 训练 predictor 或 detector，以及产物目录 |
| `data.batch_size`、`data.num_workers` | 每卡 batch 与数据加载进程数 |
| `optimization.epochs`、`optimization.max_steps` | 总 epoch / optimizer step 上限；默认 40 epochs、步数不限 |
| `optimization.accumulation_steps` | 梯度累积步数 |
| `model.*_checkpoint` | encoder、共享头和 predictor 初始化权重 |
| `runtime.limit_train_batches`、`runtime.limit_val_batches` | 每轮使用的 batch 数或数据比例 |
| `evaluation` | 独立评测的 split、batch、预测步数、事件干预、子集及输出 |
| `inference` | 独立图片推理的预测步数与分数阈值 |
| `resume_overrides` | 完整恢复时显式调整总 epoch / step 上限；默认为空 |

YAML 中的数据、权重和输出路径相对仓库根目录，`extends` 相对当前 YAML 文件。训练的 `--config`、`--resume`、`--output-dir` 也相对仓库根目录，可使用绝对路径。`--output-dir` 只覆盖本次产物位置，便于重复种子或临时运行。目录已有训练配置或 checkpoint 时，从头训练会报错，避免覆盖；可另选目录或用 `--resume` 恢复。

`runtime.limit_*_batches` 的整数表示 batch 数，浮点数表示比例：`1` 是一个 batch，`1.0` 是完整数据集，`0.25` 是四分之一。默认均为 `1.0`。这些字段用于缩小检查范围，不改变完整实验的默认预算。

预测器默认 AdamW，`betas=(0.9,0.95)`、weight decay `0.05`，predictor 与融合层学习率 `1e-4`，RVT 与 neck 学习率 `2e-4`。前 5% optimizer steps 线性 warmup，随后 cosine 下降至各参数组的绝对学习率 `1e-6`；梯度裁剪为 `1.0`。混合精度为 bf16。

每卡 batch 为 `1`，梯度累积 `8`；共享头每卡 batch 为 `4`，累积 `1`。有效 batch 为 `batch_size × GPU 数 × accumulation_steps`。默认 `40 epochs`、`max_steps=-1`、seed `42`，这是待测的运行预算。`CUDA_VISIBLE_DEVICES` 控制使用的 GPU，训练自动使用所有可见卡。

`model.predictor_checkpoint` 从相同结构的 checkpoint 初始化模型，重新建立 optimizer。RGB 初始化对照在 Event 配置中设置 `model.rgb_checkpoint`，两者不能同时设置。后者只接受与当前结构一致的 v3.1 B1 checkpoint，导入共享 predictor 参数并将事件门控置零。此配方默认共享 predictor 学习率 `2e-5`，RVT 与事件融合层 `1e-4`。旧 12 层 DINO-world 或 DINO-Foresight predictor 权重不满足当前结构；DINO encoder 预训练权重继续复用。

## 共享检测头与 checkpoint

先按 README 训练共享头，再固定它比较 B0/B1/M1/M2。检测头在目标时刻真实 RGB 的冻结 DINO 特征上训练，训练时报告的 AP 是真实帧特征的检测结果。未来预测 AP 由训练好的 predictor 和该共享头组合产生。

在 predictor 配置中设置 `model.detector_checkpoint` 后，每次验证计算冻结头 AP，`best.ckpt` 按 AP 选择；未提供共享头时按平均未来特征损失选择。`best_foreground.ckpt` 按目标帧检测框覆盖 patch 的 latent L1 选择，`last.ckpt` 保存最近训练状态。

同阶段恢复示例：

```bash
CUDA_VISIBLE_DEVICES=0 python -m foresight.train \
  --config configs/event_predictor.yaml \
  --resume outputs/v31_m2/checkpoints/last.ckpt
```

恢复包括模型、optimizer、scheduler 和训练步数，并沿用 checkpoint 中的数据与优化协议，包括 batch、累积、种子和精度。当前 YAML 可以更新数据与 encoder 路径、workers、日志频率和 batch 数量限制；predictor 的完整 checkpoint 内含验证用的共享头，恢复时直接载入它。

需要延长训练时，在 YAML 中显式设置 `resume_overrides: {epochs: 60}`，表示总共训练到 60 epochs；`max_steps` 也可在此调整。普通 `optimization` 默认值不会覆盖恢复配方。修改总预算会按新总步数重建调度函数，影响后续学习率轨迹。完整恢复保持 batch、累积与 GPU 数一致；更换 batch 的新实验应使用模型初始化权重并重新训练 optimizer。

恢复默认继续写入 checkpoint 所在运行目录，忽略预设的 `output_dir`；传 `--output-dir` 可另存。epoch 中途恢复可能重读该 epoch 开头的样本。产物包含实际配置、训练日志、验证指标和 checkpoint。

## 训练日志

在训练服务器启动 TensorBoard：

```bash
tensorboard --logdir outputs --host 127.0.0.1 --port 6006
```

Scalars 中筛选 `^monitor/`，可以集中查看训练总 loss、预测 loss、验证 loss、前景 L1、AP 和各参数组学习率。Custom Scalars 的 `Training overview` 将这些曲线放在固定面板中；预测 loss 与总目标分别展示，训练和验证的同类 epoch 指标放在同一张图。

| TensorBoard 分类 | 内容 |
| --- | --- |
| `monitor/train/`、`monitor/val/` | 日常观察的训练与验证指标 |
| `monitor/lr/` | predictor、event encoder、event fusion 或 detector 的实际学习率，按当前训练配方出现 |
| `details/loss/` | alignment、检测分类/框回归等 loss 分量 |
| `details/detector_aux/` | 检测头各辅助 decoder 层的 loss |
| `details/detection/` | AP50/AP75、尺寸 AP、AR、各类别 AP/AR 和 GT 数量 |
| `details/latent/` | 全图、前景、背景的 latent L1/cosine，前景 L1 放在 `monitor/val/` |
| `details/runtime/` | 实际有效 batch、epoch 和验证样本数 |

横轴 step 是 optimizer 更新次数。`*_step` loss 是按 `runtime.log_every` 记录的 microbatch 值；`*_epoch` loss 按样本数聚合整个 epoch。梯度累积开启时，step 曲线不代表整组累积样本的平均。AP/AR 使用 0 到 1 的数值；没有对应 GT 的类别保留 JSON 中的 `null`，不画成零。未加载共享检测头时，predictor 没有 AP 曲线。

验证的 prediction loss 汇总四个右移预测目标；区域 L1/cosine 和检测 AP 对应最后一个目标时刻。M2 的总 loss 包含加权 alignment，比较 RGB 与 Event-RGB 时应同时看 prediction loss 和下游 AP。

每次运行保存以下文件：

- `tensorboard/version_*/`：分组后的曲线与训练总览。
- `logs/version_*/metrics.csv`：保留原有指标列名，并补充学习率、完整验证标量和类别指标，供脚本分析。
- `validation_history.jsonl`：每次完成验证追加一条完整报告，包含从 0 开始的 epoch、global step、UTC 写入时间、CSV 日志目录、metrics、per-class 结果及原有 metadata。
- `metrics_val.json`：最近一次验证报告，供已有工具读取。

恢复训练会创建新的 CSV/TensorBoard version，并继续追加同一输出目录的验证历史。从较早 checkpoint 恢复时，历史中可以出现重复 step，可结合写入时间和日志 version 区分。checkpoint 继续使用原来的 `val_AP`、`val_feature_loss`、`val_foreground_l1`，分组只改变 TensorBoard 显示。已有 event 文件保留原来的标签；新的分类从下次启动或恢复训练生效。

## 评测与推理

独立评测使用 `configs/evaluate_rgb.yaml` 或 `configs/evaluate_event.yaml`。它们继承对应训练配置，用 `model.predictor_checkpoint` 指定训练完成的预测器，用 `model.detector_checkpoint` 指定共享检测头。M1 评测可继承 `event_no_align.yaml` 并指定 M1 权重与输出。配置须与预测器结构对应，所有模型使用同一个检测头。

评测命令只接受 `--config` 和可选的 `--output`。其余设置来自 YAML 的 `evaluation` 部分；它不影响训练中固定 +50 ms 的验证。

| `evaluation` 字段 | 含义 |
| --- | --- |
| `split: val` / `test` | 评测数据划分 |
| `batch_size: 1`、`max_samples: null` | 独立评测 batch 与样本数量上限；空值表示全部样本 |
| `manifest: null` | 可选样本清单；空值沿用 `data.<split>_sample_ids` 或完整划分 |
| `output` | 指标 JSON 路径，预测框另存为同名前缀的文件 |
| `event_mode: correct` | 使用真实配对历史事件 |
| `event_mode: mismatched` | 固定 RGB，替换为其他序列的完整历史事件 clip；donor 由 sample ID 确定，与 batch 顺序无关 |
| `event_mode: bin_reverse` | 在每种极性内部反转 bin 顺序，保留 clip 的时间步顺序 |
| `event_mode: zero` | 将输入事件体素置零，仍执行事件分支 |
| `event_mode: "off"` | 跳过事件编码和 Event Cross-Attention；保留引号，避免 YAML 将 off 解析为布尔值 |
| `horizon_steps: 1` / `2` / `3` / `4` | 评测 +50/+100/+150/+200 ms，分别运行并保存结果 |
| `subset: all` / `high_motion` / `nonuniform` | 全集或历史图像平面运动排名子集 |
| `top_fraction: 0.2` | 运动排名子集的比例 |
| `persistence: true` | B0：最后一帧真实 DINO 特征直接送共享头，不要求 predictor checkpoint |

例如，在 `configs/` 下新建一个继承配置，可记录错配事件的 +200 ms test 评测：

```yaml
extends: evaluate_event.yaml
evaluation:
  split: test
  horizon_steps: 4
  event_mode: mismatched
  output: outputs/v31_m2_test_mismatched_200ms.json
```

`mismatched` 的 donor 清单写入结果；评测输出保留 sample IDs。主比较使用相同样本和目标时刻。多步 rollout 将预测特征反馈到固定长度 RGB context；Event context 固定为初始观测截止前的历史特征，不生成或读取未来事件。

`high_motion` 和 `nonuniform` 默认选前 20% 样本，使用最后三个历史时刻中共同 `track_id` 的框中心。前者按最近一段像素速度模长排名，后者按相邻像素速度向量变化模长排名，每条样本取最大对象分数。它们受自车运动、透视和检测标注影响，不是物理速度、加速度或行为类别真值。子集参数与选中样本写入评测结果。

输出包括 COCO AP、AP50、AP75、尺寸分组与类别 AP，以及全图/检测框前景/背景的 latent L1 和 cosine。检测框覆盖区域不等价于真实运动区域；当前未输出独立光流动态 mask 指标。v3.1 的验收需要 M2 优于 B1，且真实配对事件优于错配、置零和关闭分支。

独立图片推理示例：

```bash
CUDA_VISIBLE_DEVICES=0 python -m foresight.infer \
  --config configs/evaluate_event.yaml \
  --images frame0.png frame1.png frame2.png frame3.png \
  --events history_events.npy \
  --output outputs/v31_prediction.json
```

四张图像按旧到新顺序提供，输入尺寸 `640×480`，相邻时刻间隔 50 ms。事件 `.npy` 必须已按上述坐标、通道与压缩约定处理，默认形状 `[4,20,512,1024]`。`inference.horizon_steps` 设置预测步数，`inference.score_threshold` 设置输出分数阈值；默认分别为 1 和 0.0。输出为原图坐标下的检测框、类别与分数。

推理命令的图像、事件和输出路径，以及评测命令临时传入的 `--output`，均相对当前 shell 目录；`--config` 与 YAML 内路径仍按仓库根目录解析。

## 代码结构与来源

```text
foresight/
  config.py                  # YAML 继承、校验与路径解析
  train.py                   # 训练 CLI
  evaluate.py                # 数据集评测 CLI
  infer.py                   # 独立图片推理 CLI
  data/                      # DSEC 读取、窗口、体素、增强与 sampler
  models/
    forecaster.py            # 冻结 DINOv2、RVT 与 predictor 的装配
    predictor.py             # 时间查询、并行预测与 rollout
    attention.py             # 3-Axial RoPE、双路 Cross-Attention、空间注意力
    rvt.py                   # RVT-S、逐像素 LSTM 与 Event neck
    checkpoints.py           # 权重加载、初始化与 checkpoint 协议校验
    detection/               # 共享 Deformable DETR、检测损失与框操作
  training/
    runner.py                # Trainer、输出目录、恢复与运行调度
    base.py                  # 数据加载、梯度归一化、optimizer 与共用验证
    predictor.py             # RGB/Event-RGB predictor 训练任务
    detector.py              # 真实 DINO 特征上的共享头训练任务
    losses.py                # Event 活跃区对齐损失
    monitoring.py            # TensorBoard、CSV 与逐轮验证报告
  evaluation/
    detection.py             # COCO 指标、样本对应与评测协议
    latent.py                # 全图、前景和背景的 latent 统计
    diagnostics.py           # 错配事件配对与运动子集
    runner.py                # 数据集评测、干预与结果导出
  inference/
    pipeline.py              # predictor + 共享头、设备与精度上下文
    images.py                # 独立图片和事件文件输入、预测结果导出
  vendor/dinov2/             # 保留的上游 DINOv2 源码
```

三个 CLI 只解析参数并调用对应模块。模型计算在 `models/`，训练任务在 `training/`；训练验证和独立评测共用 `evaluation/` 的指标实现。`evaluation` 包入口只导出指标类，推理路径不依赖 Lightning。

修改融合结构从 `models/attention.py` 和 `predictor.py` 开始；修改 Event encoder 看 `models/rvt.py`；修改监督看 `training/predictor.py` 与 `losses.py`；修改评测协议看 `evaluation/`。数据窗口与事件表示仍由 `data/` 管理。

目录整理保留 CLI、YAML 和 checkpoint 的参数键、结构元数据及格式标识。使用 Python 导入的外部脚本需要更新内部路径，例如 `foresight.models.checkpoints`、`foresight.inference.pipeline`；`from foresight.training import PredictorTask` 和 `from foresight.evaluation import FutureDetectionEvaluator` 继续可用。

方法参考 [DINO-world](https://arxiv.org/abs/2507.19468) 与 [RVT](https://github.com/uzh-rpg/RVT)。RVT 为独立实现，配置参考官方 [默认设置](https://github.com/uzh-rpg/RVT/blob/master/config/model/maxvit_yolox/default.yaml) 和 [Small 设置](https://github.com/uzh-rpg/RVT/blob/master/config/experiment/gen1/small.yaml)，FPN 按项目设计实现。保留的 DINOv2 源码与检测模块许可见 [SOURCES.json](../foresight/vendor/SOURCES.json) 和 [APACHE-LICENSE](../foresight/models/detection/APACHE-LICENSE)。
